# 설명용 대사 데모 · 분자와 분모의 범위부터 확인하기

**자료 성격: 설명용 가정 / 코드: v0.2.1 / 문서 작성: 2026-11-20**

## 질문

준비자산 1,230, 유통 잔액 1,160이면 비율은 106.03%입니다. 그러나 두 수치가 같은 범위의 자산과 의무를 나타내는지는 별도 질문입니다.

이 데모에서는 운영자금 30을 준비자산에서 제외하고 미결 상환의무 40을 의무에 포함한다고 가정합니다. 특정 회사나 USDC에서 확인한 수치가 아닙니다. 단위는 코드에 정의된 USD이며 금액을 임의로 만·백만 달러로 확대하지 않습니다.

## 입력과 계산

기준시점은 코드에서 고정한 **2026-10-31 00:00 UTC**입니다.

| 주장 | 구성 항목 | 처리 | 금액 |
| --- | --- | --- | ---: |
| A-1 | 준비자산 기초 | reserve / base | 1,230 |
| A-2 | 운영자금 | reserve / exclude | 30 |
| A-3 | 유통 잔액 | obligation / base | 1,160 |
| A-4 | 미결 상환의무 | obligation / include | 40 |

| 계산 | 결과 |
| --- | ---: |
| 조정 전 비율 | 1,230 ÷ 1,160 = 106.03% |
| 조정 준비자산 | 1,230 − 30 = 1,200 |
| 조정 상환의무 | 1,160 + 40 = 1,200 |
| 조정 후 비율 | 100.00% |
| 조정 후 차액 | 0 |

100%를 상한으로 잘라낸 결과가 아닙니다. 포함·제외 항목과 이유를 분자·분모에 각각 반영한 결과입니다. 다만 이 사례에서 조정의 경제적·법률적 적정성은 가정으로 주어집니다.

## 실행

저장소 루트에서 다음을 실행합니다. 의존 패키지 설치는 [루트 README](../README.md#quick-start)를 따릅니다.

```bash
cd implementation/chain-prism
python -m chain_prism.demo
```

[데모 코드](../implementation/chain-prism/chain_prism/demo.py)는 메모리 DB에 범위·입력·주장·구조·판단 초안·대사를 등록하고 두 개의 객체를 출력합니다.

| 출력 | 볼 항목 | 뜻 |
| --- | --- | --- |
| 첫 번째 객체: 산술 대사 | adjusted_ratio_pct = "100.00", difference_amount = "0" | 등록한 구성 항목의 계산 결과 |
| 첫 번째 객체 | auto_approved_conclusion = false | 계산으로 전문 결론을 자동 승인하지 않음 |
| 두 번째 객체: 가드레일 | ready_for_review = true | 등록한 근거 기준으로 사람의 검토를 받을 수 있는 상태 |
| 두 번째 객체 | proposal | 작성자가 제안한 등급·상태. 검토 완료 표시가 아님 |
| 두 번째 객체 | independent_evidence_count = null | 입력 개수를 독립 증거 수로 환산하지 않음 |

출력은 단일 JSON 배열이 아니라 객체 두 개가 연속되는 텍스트입니다. 기존 [demo-result.json](../implementation/chain-prism/demo-result.json)도 이 형식의 출력 기록이므로 파일 전체를 하나의 JSON 문서로 파싱하면 실패합니다.

주장의 F 표시는 **설명용 입력에 그 값이 적혀 있다는 관찰**입니다. 가상의 수치가 실제로 존재하는 준비자산이라는 의미가 아닙니다. 자료 성격 illustrative와 관찰 범위도 함께 읽어야 합니다.

## 데모가 끝난 뒤에도 남는 일

기본 데모는 ReviewRequest 제출이나 최종 결론 고정을 수행하지 않습니다. 그 기능은 엔진·API와 별도 테스트에 있습니다.

실제 적용에서는 승인·계좌·고객원장의 모집단과 시점을 확인하고, 항목의 중복·누락 및 조정 이유를 검토해야 합니다. 자산 실재, 처분 가능성, 상환권, 통제 효과성은 산술 일치만으로 입증되지 않습니다.

현재 데모의 AnalysisUnit에는 module="M3"가 기록되어 있습니다. 이는 코드의 기존 태그이며 이 산술 사례가 조세 판단을 수행했다는 뜻은 아닙니다. 모듈 태그와 방법론 판본의 대응은 후속 정비 대상입니다.

## 이 작업이 보여주는 관점

**비율을 해석하기 전에, 무엇이 분자와 분모에 들어갔는지 확인합니다.** 구현은 계산·근거 연결·검토 경계를 재현하고, 사람은 조정의 근거와 전문적 결론을 책임집니다.
